OmniRoute: a free fallback gateway for our AI coding tools

How to install and run the OmniRoute gateway on your machine, and connect Claude Code, Cline, and Codex to it — so you can keep working on free models whenever your main AI subscription hits its usage limit.

macOS · Linux Node.js ≥ 18 localhost:20128 Sept 2026

1What is OmniRoute?

OmniRoute (github.com/diegosouzapw/OmniRoute) is an open-source, self-hosted LLM gateway. It runs entirely on your own machine and exposes one local API endpoint that stands in front of 350+ AI providers and 1,200+ models. Your coding tools talk to the gateway; the gateway picks a working model — falling back automatically when a provider is down or its quota is used up.

Why we use it

  • Free fallback. When a Claude / Cursor / Copilot usage limit is reached mid-task, you switch to the gateway and keep working on free models until the limit resets. You register a handful of free-tier API keys once (section 4); the gateway then rotates across them automatically.
  • One endpoint for every tool. Terminal agents, VS Code extensions, and its own web playground all point at the same local address.
  • Local-first. The gateway, its dashboard, and its request logs run on your machine. Any provider keys you add are stored encrypted (AES-256-GCM).

What to expect

  • Free models are noticeably weaker than Claude / GPT-class models. Fine for small edits, questions, boilerplate; save complex work for your main subscription.
  • Requests routed to free providers leave your machine and pass through those third-party services. Check your organisation's policy before using it on sensitive code.

2Installation

Requires Node.js 18 or newer (node --version to check). Then:

npm install -g omniroute

The first run creates its data directory at ~/.omniroute/ (settings, request logs, encrypted key store, SQLite database).

Every fresh install uses the well-known password CHANGEME. Sign in once and change it in the dashboard settings — especially before adding any real provider API keys.

Start automatically at login

omniroute autostart enable

On macOS this writes a LaunchAgent (~/Library/LaunchAgents/com.omniroute.autostart.plist); on Linux, a systemd user service. Note: the LaunchAgent pins the absolute path of your current Node version — if you upgrade Node with nvm, run omniroute autostart enable again.

4Free providers & API keys

Since September 2026 the keyless providers OmniRoute shipped with no longer accept outside traffic (OpenCode's free tier now answers “can only be used from within OpenCode” — HTTP 403). The gateway therefore needs a few free-tier API keys — each takes about two minutes to create and costs nothing. With several registered, the auto model rotates across all of them and fails over when one hits its daily quota.

Providers we currently use

All five work without a credit card. Cerebras also has a free tier but asks for a card at sign-up, so we skip it.

Registering a key — dashboard

  1. Open http://localhost:20128 and sign in
  2. Go to Settings → Providers
  3. Pick the provider (Gemini, Groq, …), paste the key, and save

Registering a key — terminal

# example: add a Groq key (stdin keeps it out of shell history)
printf '%s' 'gsk_YOUR_KEY_HERE' | omniroute providers add groq --credential-stdin --yes

# confirm and check key health
omniroute providers list
omniroute providers status

Keys are stored encrypted (AES-256-GCM) in ~/.omniroute/. To replace an expired or leaked key: omniroute providers rotate <name>.

5Integrating Claude Code

We use an opt-in shell alias rather than OmniRoute's setup-claude command. The alias gives you a second command that routes through the gateway, while plain claude (and the Claude Code VS Code extension) keep using your Anthropic subscription untouched.

Add this once to ~/.zshrc (or ~/.bashrc):

alias claude-omni='ANTHROPIC_BASE_URL=http://localhost:20128 \
  ANTHROPIC_AUTH_TOKEN=omniroute \
  ANTHROPIC_SMALL_FAST_MODEL=auto \
  ANTHROPIC_DEFAULT_HAIKU_MODEL=auto \
  claude --model auto'

Then reload with source ~/.zshrc. Day to day:

You typeWhat happensWhen
claudeNormal Claude Code on your Anthropic subscriptionEvery day
claude-omniClaude Code through OmniRoute, on free modelsUsage limit reached

Three details that matter

  • Base URL has no /v1. Claude Code appends /v1/messages itself. With /v1 in the URL, requests 404.
  • --model auto must be a CLI flag. Claude Code ignores the ANTHROPIC_MODEL environment variable and keeps requesting its real model name, which the gateway rejects with “400 — Unable to determine provider for model 'claude-…'”. The flag forces auto, which OmniRoute routes to whatever free model is available.
  • Ignore the catalog warning. On startup you'll see “'auto' isn't described by this version's model catalog” — harmless; Claude Code just assumes a safe 200k context window.
Avoid omniroute setup-claude

That command rewrites your global Claude Code configuration so every session — including the VS Code extension — goes through the gateway. If the gateway is down, everything breaks. The alias keeps the switch per-terminal and reversible.

6Integrating Cline, Codex, and Cursor

Cline (VS Code extension) — recommended

Cline runs on your machine, so it reaches localhost directly. In the Cline sidebar, open ⚙ Settings → API Configuration and set:

FieldValue
API ProviderOpenAI Compatible
Base URLhttp://localhost:20128 — without /v1; Cline appends it
API Keyany value, e.g. omniroute (the local gateway doesn't require a real key)
Model IDauto

Codex CLI

OmniRoute ships a dedicated launcher, so there is nothing to configure by hand:

# one-time install of the Codex CLI
npm install -g @openai/codex

# launch Codex already pointed at the gateway
omniroute launch-codex

For a permanent profile instead of the launcher: omniroute configure codex --model auto --yes writes one into ~/.codex/config.toml.

Cursor — not recommended

The Cursor editor cannot use a localhost gateway: when you give Cursor a custom API key or base URL, requests are sent from Cursor's cloud servers, which cannot reach an address on your machine. Verification simply fails — it is an architectural limit, not a settings problem.

The only workaround is exposing your gateway on a public URL (omniroute tunnel) and pasting that into Cursor's “Override OpenAI Base URL”. That puts your gateway on the open internet, so it demands a strong dashboard password and a real gateway API key first. For most of us: use Cursor on its own models, and take the free fallback in Claude Code or Cline instead.
